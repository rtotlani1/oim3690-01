### Interaction 1

- **What I asked**: How will geolocation code actually get a user's location?
- **What AI gave me**: 
Browser geolocation works through the Geolocation API, built into JavaScript. Here's the flow:

1. You call navigator.geolocation.getCurrentPosition()

javascript
navigator.geolocation.getCurrentPosition(
  (position) => {
    const lat = position.coords.latitude;
    const lon = position.coords.longitude;
    console.log(lat, lon);
  },
  (error) => {
    console.error("Location error:", error.message);
  }
);

It takes two callbacks — one for success, one for failure (user denies permission, timeout, etc).

2. The browser asks the user for permission

The first time a page calls this, the browser pops up a native "Allow this site to access your location?" prompt. Nothing happens until the user clicks Allow. If they click Block, your error callback fires instead.

3. Under the hood, the browser figures out the location using whatever signals it has available, roughly in order of accuracy:

GPS chip — most accurate, mainly on phones/laptops with GPS hardware
Wi-Fi positioning — matches nearby Wi-Fi network signatures against Google/Apple's location databases (this is how laptops without GPS still get decent accuracy)
Cell tower triangulation — on mobile data
IP address geolocation — least accurate (city-level at best), used as a fallback

You don't choose which one — the browser/OS picks automatically based on what's available and how much accuracy you request.

4. It's HTTPS-only. Geolocation won't work on plain http:// pages (except localhost, which is treated as secure for dev purposes). So if you're testing locally it's fine, but once deployed on GitHub Pages, it'll work automatically since Pages serves over HTTPS.
