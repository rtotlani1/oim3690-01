### Interaction 1

- **What I asked**: if I want to add image animations to my website, can it be done with JS alone or we need an API for that
- **What AI gave me**: 
Short answer: JS (and honestly, mostly CSS) alone is enough — no API required for animations. APIs come into play only if you want to generate images (AI-generated art) or fetch external image content, not to animate what's already there.

Here's the breakdown:

Pure CSS — best for most simple animations
For hover effects, transitions, fades, slides, spins:

css
img {
  transition: transform 0.3s ease;
}
img:hover {
  transform: scale(1.1) rotate(3deg);
}

Or @keyframes for more complex, looping animations:

css
@keyframes float {
  0%, 100% { transform: translateY(0); }
  50% { transform: translateY(-15px); }
}
img {
  animation: float 3s ease-in-out infinite;
}

This runs entirely in the browser, no JS needed at all.

JS — for animations that respond to logic/events
Use JS when you need to trigger, sequence, or control animations based on something happening — a click, scroll position, timer, API response, etc.

javascript
const img = document.querySelector("#hero-img");
img.addEventListener("click", () => {
  img.classList.toggle("spin"); // toggles a CSS class that has the animation
});

The common pattern is: JS adds/removes a CSS class, and CSS actually does the animating. That combo covers 95% of use cases.

JS for more advanced control — things like scroll-triggered animations, staggered sequences, or physics-like motion — you'd use the Web Animations API (built into the browser, no external API/library needed):

javascript
img.animate(
  [{ transform: "translateX(0)" }, { transform: "translateX(100px)" }],
  { duration: 1000, iterations: Infinity, direction: "alternate" }
);

When you'd actually need an API:

Generating a new image (DALL-E, Stability AI, etc.) — that's content creation, not animation
Fetching a GIF/image from somewhere (like Giphy's API) if you want pre-made animated content
Turning static images into AI-animated video (like Runway) — that's a heavier, server-side task

So for your OIM3690 project — if you just want polish (things fading in, buttons that pulse, cards that lift on hover), stick to CSS transitions/keyframes with JS only handling the trigger logic. No API needed.
